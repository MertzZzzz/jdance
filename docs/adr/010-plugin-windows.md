# ADR-010: Окна редакторов плагинов

- Статус: ACCEPTED
- Дата: 2026-10-20
- Требования: PLG-060..065, ADR-002

## Контекст

VST3-редактор встраивается в нативное окно хоста: `HWND` на Windows,
`NSView` на macOS, X11 window ID на Linux. Главное окно приложения —
eframe/winit; на Linux оно может работать через Wayland, а VST3 GUI на
Linux поддерживает только X11.

## Варианты

1. Viewport'ы egui как окна плагинов: нет стабильного доступа к их
   native handle, и окно рисует egui.
2. Собственное нативное top-level окно на каждый редактор, отдельно от
   egui.
3. Перевести всё приложение на X11 (XWayland) под Wayland.

## Решение

Вариант 2. `plugin-vst3/src/editor` создаёт окно средствами ОС:

- Linux: X11 через `x11rb` (pure Rust); под Wayland — через XWayland,
  главное окно при этом может остаться на Wayland. Хост реализует
  `IRunLoop` (fd и таймеры плагина) и обслуживает его в UI-кадре; пока
  редактор открыт, UI перерисовывается непрерывно. Без X-сервера
  редактор не открывается, остаётся generic editor с объяснением.
- Windows: Win32-окно (`windows-sys`); сообщения диспетчеризует общий
  цикл приложения, хост дополнительно выбирает сообщения своего окна.
- macOS: `NSWindow` (`objc2-app-kit`) только в main thread.

`IPlugFrame::resizeView` меняет размер окна и вызывает `onSize`;
пользовательский resize разрешён, только если `canResize` и
`checkSizeConstraint` согласны, иначе размер откатывается. Закрытие
окна уничтожает только view (`removed`), экземпляр остаётся (PLG-063);
при удалении плагина окно закрывается раньше экземпляра.

## Последствия

- Окна редакторов не принадлежат главному окну (owner не задаётся):
  нужен доступ к native handle главного окна eframe — отдельная задача.
- HiDPI (`IPlugViewContentScaleSupport`) и обработка клавиатуры для
  плагинов пока не реализованы.
- Проверено тестовым плагином на X11 (Xvfb, CI) и в CI на Windows и
  macOS; реальные плагины с GUI — Milestone P3.
