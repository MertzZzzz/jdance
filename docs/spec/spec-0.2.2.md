# Спецификация 0.2.2 — аудиоканалы в Channel Rack и ASIO-host

Статус: черновик v1, 2026-10-22. Базируется на 0.2.1. Дополняет
`spec-0.2.0.md`, Amendment 01 и Amendment 02 и заменяет их в пунктах,
перечисленных в §0.3.

## 0. Общие положения

### 0.1. Цель релиза

1. **Аудиоканалы.** Любой сэмпл, попавший в Playlist, — перетащенный из
   библиотеки, Project Browser или системы, поставленный Draw/Paint,
   вынесенный из Sample Editor, записанный или пришедший из старого
   проекта, — появляется в Channel Rack как канал. Канал можно выделить,
   переименовать, заглушить, изменить громкость и панораму и направить в
   любой трек микшера. Все клипы этого сэмпла в Playlist звучат через
   канал (ACH-015).
2. **ASIO-host.** На Windows приложение работает через установленные
   ASIO-драйверы сторонних производителей: воспроизведение, запись
   выбранного входа, панель драйвера, смена конфигурации драйвером.

### 0.2. Clean room

**CR-010.** Референс поведения — pattern-based DAW (FL Studio). Источник
требований — только публичное руководство пользователя Image-Line и
общеизвестные приёмы работы в DAW (CR-001, CR-003). Не используются
бинарники, ресурсы, файлы проектов и внутренние документы референса
(CR-002). Названия, иконки, тексты, цвета и геометрия — свои (UI-VIS-002).

**CR-011.** Из руководства берётся *модель работы*: аудиоклип в Playlist
является экземпляром канала в Channel Rack; канал направляется в трек
микшера; запись идёт через ASIO-драйвер. Реализация, формат проекта и
структура данных — собственные.

**CR-012.** ASIO: источник — публичная документация и заголовки ASIO SDK
Steinberg под лицензией GPLv3 (ASIO-002). Собственный ASIO-драйвер
референса не анализируется и не используется для разработки; как
внешний клиент он допустим только в Driver track (DRV-001).

**CR-013.** Пометки в тексте, как в UI-VIS-004:
- **[Д]** — поведение описано в документации референса (по выдержкам);
- **[?]** — выдержки неполны, сверить с полным текстом;
- **[Н]** — наше решение.

Источники для этого документа добавляются в
`docs/provenance/sources.md`:
- `html/playlist_audioclip.htm`;
- `html/chansettings_sampler.htm`;
- `html/recording_audio.htm`;
- `html/envsettings_audio.htm`;
- `html/mixer_iorouting.htm`;
- ASIO SDK (версия и лицензия — ASIO-030).

### 0.3. Что меняется в действующих документах

| Документ, пункт | Было | Стало |

### 0.4. Вне scope 0.2.2

- Вход трека микшера и запись с нескольких входов одновременно
  (поле «Вход» в инспекторе микшера остаётся выключенным, UI-VIS-093).
- Автоматизация громкости и панорамы канала.
- Time stretch и pitch аудиоканала.
- Группы фильтра каналов, кроме перечисленных в ACH-032.
- Несколько ASIO-устройств одновременно, агрегация устройств.
- Собственный ASIO-драйвер (Driver track, DRV-000).
- 32-битные ASIO-драйверы (приложение 64-битное, ASIO-003).

## Часть 1. Аудиоканалы

### 1.1. Модель

**ACH-001.** Новый вид источника канала — **аудиоканал**:

```
ChannelSource::Audio { asset: AssetId }
```

Аудиоканал ссылается ровно на один AudioAsset. Один AudioAsset может
принадлежать нескольким аудиоканалам (после «Make unique», ACH-024).

**ACH-002.** AudioClip ссылается на канал, а не на asset:

```
AudioClip {
  id, lane, channel: ChannelId,   // было: asset: AssetId
  start, source_in, source_out, gain, muted, fade_in, fade_out
}
```

Asset клипа определяется каналом. Инварианты (проверяются при загрузке
и в командах):
- `channel` существует и это аудиоканал;
- `source_in < source_out <= asset.frames` для asset этого канала.

**ACH-003.** Параметры аудиоканала: имя, цвет, громкость
(`0..=MAX_VOLUME`), панорама, mute, трек микшера. Поля
`pitch`, `polyphony`, `mono` у аудиоканала не используются и не
показываются. Шагов и нот у аудиоканала нет: паттерн не может содержать
шаги или ноты аудиоканала, команды это отклоняют.

**ACH-004.** Каналы — в одном списке Channel Rack: инструменты и
аудиоканалы идут вперемешку в порядке, заданном пользователем, ID
каналов общие.

### 1.2. Сигнальный путь

**ACH-010.** Для каждого звучащего экземпляра (AudioClip):

```
asset → ресемплинг → source range → anti-click и fade_in/fade_out
  → gain клипа (и его автоматизация, spec-0.2.0 §11)
  → сумма экземпляров канала
  → громкость канала → панорама канала → mute канала
  → вход трека микшера канала
```

Mute клипа, mute и solo дорожки Playlist действуют как в 0.2.0.

**ACH-011.** Панорама аудиоканала — **баланс** (`balance_gains`, единица
в центре), а не constant-power закон каналов-инструментов (`pan_gains`,
−3 dB в центре) [Н]. Причины: материал стереофонический, а мигрированный
проект при громкости 1.0 и панораме 0 должен звучать так же, как в 0.2.x
(ACH-063).

**ACH-012.** Изменения громкости и панорамы канала сглаживаются так же,
как у каналов-инструментов (без zipper noise). Mute канала — с коротким
фейдом, без щелчка.

**ACH-013.** Граф маршрутизации (MIX-001): аудиоканал — узел-источник с
одним ребром main out в трек микшера. Правила ацикличности и PDC
(MIX-002, MIX-030) распространяются на него без изменений.

**ACH-014.** Offline render и экспорт WAV/MP3 используют тот же путь,
что и воспроизведение.

### 1.3. Любой сэмпл в Playlist — канал в Channel Rack

**ACH-015. Инвариант.** В проекте нет AudioClip без аудиоканала: каждый
клип в Playlist — экземпляр канала, видимого в Channel Rack. Способ, которым
сэмпл попал в Playlist, значения не имеет [Д: у референса каждый
аудиоклип имеет канал в Channel Rack].

**ACH-016.** Инвариант обеспечивает слой команд, а не UI:
- команда добавления клипа принимает канал; клип с несуществующим или
  не-аудиоканалом отклоняется (ACH-071);
- для размещения *файла или asset* есть одна команда «поставить
  сэмпл»: она находит или создаёт канал (ACH-020) и добавляет клипы —
  атомарно, одним шагом отмены. Все пути из ACH-017 идут через неё;
- загрузка проекта проверяет инвариант; нарушение — ошибка загрузки с
  понятным сообщением, а не молчаливое «починить» (кроме миграции
  v12 → v13, ACH-061).

**ACH-017.** Пути, по которым сэмпл попадает в Playlist, и что происходит
с каналом:

| Путь | Канал |
|---|---|
| Перетаскивание файла из Browser (папки библиотеки, избранное, поиск) | найти или создать (ACH-020) |
| Перетаскивание файла из файлового менеджера ОС (один или несколько файлов) | найти или создать для каждого файла |
| Перетаскивание сэмпла из Project Browser › Samples | найти или создать |
| Draw / Paint с выбранным в Project Browser сэмплом | найти или создать |
| Перетаскивание аудиоканала из Channel Rack или Project Browser | этот канал (ACH-035, ACH-042) |
| Draw / Paint с выбранным аудиоканалом | этот канал (ACH-043) |
| Sample Editor «Поставить выделение в Playlist» | канал редактируемого клипа; если редактор открыт для файла без клипа — найти или создать |
| Slice, Duplicate, копирование и вставка клипа, Paint копий | канал исходного клипа (ACH-023) |
| Make unique | новый канал (ACH-024) |
| Запись | всегда новый канал (REC-001) |
| Открытие проекта 0.2.x | каналы создаёт миграция (ACH-061) |

Импорт файла *без* размещения (Project Browser › Samples «Импорт») канала
не создаёт: в Playlist сэмпла ещё нет. Канал появится при первом
размещении [Н].

**ACH-018.** Новый канал сразу виден: Channel Rack прокручивается к нему
и подсвечивает строку на 1 с [Н]. Если строку скрывает фильтр «Instruments»
(ACH-032), строка состояния сообщает «Аудиоканал «<имя>» создан (скрыт
фильтром)» [Н]. Если Channel Rack закрыт, он не открывается сам.

**ACH-019.** Перетаскивание нескольких файлов сразу — один шаг отмены на
весь бросок: все asset, каналы и клипы появляются и отменяются вместе.

### 1.4. Создание аудиоканалов

**ACH-020.** Перетаскивание файла (из Browser, Project Browser или
системы) на Playlist создаёт AudioClip и:
- если у этого asset уже есть аудиоканал — клип становится его
  экземпляром, новый канал **не** создаётся (решение владельца продукта,
  2026-10-22). Если каналов у asset несколько (после Make unique) —
  первый по порядку в Channel Rack;
- «тот же файл» — тот же asset: импорт уже сводит файлы с одинаковым
  содержимым (хеш и размер) к одному asset, даже если они лежат по
  разным путям;
- иначе создаётся новый аудиоканал: имя = имя файла без расширения,
  цвет — следующий из палитры, трек микшера — Master [Д: новые каналы
  идут в Master].

Импорт asset и создание канала и клипа — **один шаг отмены**.

**ACH-021.** Перетаскивание файла на Channel Rack по-прежнему создаёт
**сэмплер** (0.2.x). Аудиоканал из Channel Rack не создаётся: у
аудиоканала без клипов нет смысла [Н].

**ACH-022.** Запись (spec-0.2.0 §7) создаёт для каждого дубля новый
аудиоканал и клип на дорожке, где шла запись (REC-001).

**ACH-023.** Slice, копирование, Paint и Duplicate клипа создают
экземпляры **того же** канала. Изменение громкости, панорамы или трека
канала слышно во всех экземплярах [Д].

**ACH-024.** «Make unique» в меню аудиоклипа: новый аудиоканал с тем же
asset, копией параметров исходного канала и именем «<имя> 2»; клип
переходит в него. Файл не копируется [Д]. Один шаг отмены.

**ACH-025.** «Make unique» доступен и для нескольких выделенных клипов
одного канала: все они переходят в один новый канал [Н].

### 1.5. Channel Rack

**ACH-030.** Строка аудиоканала (UI-VIS-061) — те же колонки 1–6, что у
инструмента: mute, pan, volume, трек микшера, кнопка-имя, индикатор
выделения [Д]. Вместо шагов (колонка 7):
- мини-волна asset на всю ширину колонки, высота строки [Н];
- справа поверх волны — число экземпляров в Playlist: «3 clips» [Н];
- клик по волне — выделить все экземпляры канала в Playlist и
  прокрутить к первому [Н];
- двойной клик — Sample Editor первого экземпляра [Н].

Отличие от инструмента видно сразу: значок волны в кнопке-имени и тип
«Audio» справа вместо «Sampler» [Н].

**ACH-031.** Клик по кнопке-имени открывает **настройки аудиоканала**
(окно Channel Settings в режиме аудио) [Д: настройки аудиоклипа
открываются из Channel Rack]:
- имя, цвет;
- громкость, панорама, трек микшера;
- файл: имя, путь, частота, каналы, длительность; «Показать в
  Browser»;
- число экземпляров;
- кнопки «Выделить экземпляры в Playlist», «Sample Editor».

Секций сэмплера (ADSR, root key, loop, pitch, polyphony) у аудиоканала
нет.

**ACH-032.** Фильтр каналов в шапке Channel Rack (UI-VIS-060, п. 2):
«All · Instruments · Audio». «Audio» показывает только аудиоканалы [Д/?:
у референса аудиоклипы попадают в отдельную группу фильтра]. Выбор
фильтра — состояние вида, в проект не пишется.

**ACH-033.** Выделение, Ctrl+L, Alt+C, Alt+Del, Alt+↑/↓ (UI-VIS-064)
работают для аудиоканалов:
- **Ctrl+L** — направить выделенные каналы (инструменты и аудио) в
  выделенный трек микшера, одним шагом отмены [Д];
- **Alt+C** — клон аудиоканала: тот же asset и параметры, без клипов [Н];
- **Alt+Del / «Удалить»** — удаляет канал **и все его клипы** после
  подтверждения «Удалить канал и N клипов в Playlist?»; один шаг отмены,
  undo возвращает канал и клипы [Д/?];
- перемещение — меняет только порядок строк.

**ACH-034.** Удаление последнего клипа канала канал не удаляет [Д/?].
Команда «Удалить неиспользуемые аудиоканалы» в меню Channel Rack
удаляет аудиоканалы без клипов одним шагом отмены и сообщает их число
[Н]. Asset при этом не удаляется (spec-0.2.0 §13: orphan assets
удаляются только явной очисткой).

**ACH-035.** Перетаскивание строки аудиоканала из Channel Rack на
Playlist создаёт экземпляр этого канала в месте отпускания [Н].

**ACH-036.** Правый клик по кнопке-имени аудиоканала — меню:
переименовать, цвет, трек микшера ▸, Make unique (новый канал с тем же
asset, без клипов), выделить экземпляры, удалить [Н].

### 1.6. Playlist и Project Browser

**ACH-040.** У дорожек Playlist больше нет маршрута аудио: поле трека
микшера в заголовке дорожки удаляется (UI-VIS §7.2). Дорожка — только
место на временной шкале [Д: у референса дорожки Playlist не
маршрутизируются].

**ACH-041.** Клип показывает цвет **канала**; имя в полосе имени — имя
канала [Д]. Меню клипа (маркер ▾ или Shift + правый клик) получает
пункты: «Канал: <имя>» (выделить канал в Channel Rack), «Make unique»,
«Трек микшера ▸» (меняет трек **канала**, подсказка «влияет на N
клипов») [Н].

**ACH-042.** Project Browser › Samples показывает asset и под ним его
аудиоканалы с числом экземпляров; перетаскивание канала на Playlist —
как ACH-035, перетаскивание asset — как ACH-020 [Н].

**ACH-043.** Draw и Paint с выбранным в Project Browser аудиоканалом
ставят его экземпляры [Н].

**ACH-044.** Инструмент Slice и Sample Editor меняют только экземпляр
(source range), не канал и не asset (как в 0.2.0).

### 1.7. Микшер

**ACH-050.** Индикатор «откуда приходит сигнал» в микшере (подсветка
треков, в которые идут выделенные каналы) учитывает аудиоканалы [Д/?].

**ACH-051.** Удаление трека микшера переводит его аудиоканалы в Master,
как каналы-инструменты (MIX-022 по аналогии); undo возвращает маршрут.

### 1.8. Формат проекта и миграция

**ACH-060.** Формат проекта — версия **13**:
- `ChannelSource::Audio { asset }`;
- `AudioClip.channel` вместо `AudioClip.asset`;
- `Lane.audio_track` удалён.

**ACH-061.** Миграция v12 → v13:
1. Для каждой пары (asset, `audio_track` дорожки клипа) создаётся один
   аудиоканал: asset этой пары, трек = `audio_track`, громкость 1.0,
   панорама 0, mute выключен, имя = имя asset (при нескольких каналах
   одного asset — «<имя> → <имя трека>»).
2. Каналы добавляются в конец Channel Rack в порядке первого появления
   клипа на временной шкале.
3. Каждый клип получает канал своей пары.
4. `Lane.audio_track` отбрасывается.

Миграция детерминирована: один и тот же файл v12 даёт один и тот же v13.

**ACH-062.** Мигрированные проекты не перезаписываются при ошибке
миграции; перед первым сохранением создаётся резервная копия (как
spec-0.2.0 §13).

**ACH-063.** Сохранность звучания: render мигрированного проекта
совпадает с render того же проекта в 0.2.1 (разница отсчётов не больше
1e-6). Проверяется golden-тестом на проекте с аудиоклипами на дорожках с
разными маршрутами.

**ACH-064.** Автоматизация `AudioClipGain(ClipId)` сохраняется без
изменений.

### 1.9. Команды и отмена

**ACH-070.** Новые команды (crate `commands`), каждая — один шаг отмены:
- добавить аудиоканал (с клипом или без);
- изменить asset аудиоканала (только из Sample Editor «Заменить файл»
  [Н], с проверкой range всех экземпляров);
- перенести клипы в канал (Make unique);
- удалить канал с его клипами;
- направить каналы в трек (Ctrl+L).

**ACH-072.** Тест инварианта: для каждого пути из таблицы ACH-017 —
тест на уровне команд (и, где путь начинается в UI, — сценарий под
Xvfb), который проверяет: после действия у каждого клипа есть
аудиоканал, канал есть в Channel Rack, undo убирает канал, созданный этим
действием, и не трогает существующие.

**ACH-071.** Команды отклоняют до изменения документа:
- клип без канала или со ссылкой на не-аудиоканал (ACH-015);
- шаги и ноты для аудиоканала;
- source range за пределами asset канала.

## Часть 2. Запись в аудиоканал

**REC-001.** Каждый дубль записи (spec-0.2.0 §7) создаёт **одним шагом
отмены**: AudioAsset, аудиоканал и AudioClip на записанной дорожке.

**REC-002.** Имя канала дубля: «<имя входа> · <номер дубля>», например
«Input 1+2 · 3»; номер — следующий в проекте [Н]. Имя asset — то же.

**REC-003.** Трек микшера нового канала задаётся полем **«В трек»** рядом
с выбором входа (Options › Recording и всплывающая панель записи) [Н]:
- «Master» — по умолчанию [Д: записанные клипы по умолчанию идут туда
  же, куда входной трек, обычно в Master];
- любой существующий трек;
- «Новый трек» — создаётся трек с именем входа; следующий дубль с тем же
  входом идёт в тот же трек.

Выбор хранится в проекте (настройка записи проекта), а не в
пользовательских настройках: разные проекты пишут в разные треки.

**REC-004.** Мониторинг входа во время записи не идёт через трек
нового канала (канала ещё нет): путь мониторинга остаётся как в 0.2.0.
После записи канал звучит через свой трек, как любой аудиоканал.

**REC-005.** Undo дубля убирает канал, клип и asset из проекта, файл на
диске остаётся до явной очистки (spec-0.2.0 §7 «Recovery»).

**REC-006.** Восстановленный после сбоя дубль (Recovery) добавляется в
сэмплы проекта, как в 0.2.0: позиция дубля после сбоя неизвестна, поэтому
клип не создаётся. Канал появляется при размещении сэмпла в Playlist
(ACH-017). [Уточнено при реализации 0.2.2.]

## Часть 3. ASIO-host

### 3.1. Решение ADR-006 и устройство crate

**ASIO-011.** До кода — таблица `docs/audio/cpal-capabilities.md`
(BLD-030) для закреплённой версии CPAL (0.18.2) и строки ASIO:
enumeration, имена каналов, sample rates, buffer constraints, latency,
control panel, `kAsioResetRequest`, `kAsioBufferSizeChange`, вход и выход
в одном `bufferSwitch`, требования к сборке. Каждая ячейка — с
источником (код CPAL или документация), без догадок.

**ASIO-012.** ADR-006 принимается по таблице ASIO-011:
- если CPAL закрывает ASIO-003…009 и ASIO-020…045 — backend строится на
  CPAL feature `asio`, недостающее не изобретается вокруг CPAL;
- иначе — собственный адаптер `crates/audio-asio` (ASIO-001). Ожидаемый
  исход [VERIFY]: собственный адаптер (BLD-031: в CPAL нет control panel
  и обработки сообщений драйвера).

**ASIO-013.** Собственный адаптер, если выбран:
- вызывает драйвер как COM-объект напрямую из Rust (`CoCreateInstance`
  по CLSID из реестра, ASIO-003) через описание интерфейса драйвера и
  структур, переписанное по заголовкам ASIO SDK (GPLv3, ASIO-030) [Н];
- C++-часть SDK (`asio.cpp`, `asiodrivers.cpp`) не компилируется, libclang
  и bindgen не нужны [Н]; если это невозможно — ADR фиксирует причину и
  сборочные зависимости;
- `unsafe` разрешён только в этом crate (`#![allow(unsafe_code)]`, как
  `plugin-vst3`), каждый блок — с комментарием SAFETY;
- callbacks драйвера не имеют пользовательского указателя: состояние
  активного драйвера — одна статическая ячейка, поэтому одновременно
  открыт один драйвер (Amendment 01 §6).

**ASIO-014.** Crate собирается только под `cfg(windows)` и feature
`asio` (ASIO-001). Release-сборка для Windows (MSI) включает feature.
Сборки Linux и macOS и Windows без feature не меняются.

### 3.2. Драйверы и настройки

**ASIO-020.** В Options › Audio backend «ASIO» стоит первым в списке на
Windows, когда найден хотя бы один драйвер. Список драйверов —
из реестра (ASIO-003); недоступный драйвер виден с причиной («не
создаётся: код …», «занят другим приложением») [Н].

**ASIO-021.** ID устройства — CLSID драйвера (стабильный, AUD-012);
показывается имя драйвера. Настройки хранятся по ключу
`("asio", CLSID)`.

**ASIO-022.** Экран настроек ASIO показывает и использует
(AUD-011, Amendment 01 §5):
- выбор драйвера;
- кнопку **«Панель драйвера»** — открывает панель настроек драйвера
  [Д: размер буфера на Windows меняется в панели драйвера];
- sample rate: список из значений, которые драйвер принимает
  (`ASIOCanSampleRate` по ряду 44.1/48/88.2/96/176.4/192 kHz);
- размер буфера: если драйвер даёт выбор (`ASIOGetBufferSize`,
  ASIO-006), список допустимых значений; иначе — значение драйвера и
  подсказка «меняется в панели драйвера»;
- пересчёт буфера в мс при текущей частоте [Д];
- пару выходов с именами каналов драйвера: «Out 1+2 (Main L/R)»;
- число входов и их имена (для записи, ASIO-040);
- фактическую конфигурацию: частота, буфер, формат, задержки входа и
  выхода от драйвера в отсчётах и мс;
- состояние и последнюю ошибку.

**ASIO-023.** Имена каналов: `ASIOGetChannelInfo`. В `audio-api`
добавляется получение имён входов и выходов устройства; CPAL-backend'ы
возвращают «Input N» / «Output N». `InputChannels::label` берёт имена
драйвера, если они есть («Input 1+2 (Mic 1/Mic 2)»).

**ASIO-024.** Сохранённый драйвер не найден при запуске: уведомление,
предложение выбрать устройство, без молчаливого переключения на WASAPI
(Amendment 01 §5, AUD-004).

**ASIO-025.** Опция «Освобождать ASIO-драйвер, когда окно jdance не
активно» — выключена по умолчанию [Д/?: у референса есть автоматическое
закрытие устройства]. Включённая: при потере фокуса и остановленном
транспорте драйвер закрывается, при возврате фокуса — открывается с
той же конфигурацией. Во время воспроизведения или записи драйвер не
закрывается.

### 3.3. Поток и формат

**ASIO-030.** Лицензия и происхождение (уточнение ASIO-002):
- зафиксировать версию ASIO SDK и текст GPLv3-лицензии в
  `docs/dependencies.md` и `docs/provenance/sources.md` [VERIFY: версия,
  с которой действует GPLv3];
- файлы SDK в репозиторий не кладутся; в коде — только переписанные
  определения интерфейса с указанием источника;
- в About и в лицензионных файлах MSI — уведомление об ASIO SDK под
  GPLv3; название «ASIO» без логотипа до проверки правил товарного знака
  [VERIFY].

**ASIO-031.** Открытие (non-RT поток с COM STA, ASIO-004):
`ASIOInit` → каналы и форматы → sample rate → `ASIOCreateBuffers` для
выбранной пары выходов и выбранных входов записи → `ASIOGetLatencies` →
`ASIOStart`. Таймаут каждого шага — 5 с (ASIO-009); при таймауте
драйвер считается зависшим, ошибка показывается, UI не блокируется.

**ASIO-032.** `bufferSwitch` / `bufferSwitchTimeInfo` (RT, раздел 8
Amendment 01):
1. входы выбранных каналов конвертируются в предвыделенные f32-буферы
   и передаются capture-callback'у записи и монитора;
2. engine рендерит стерео-блок размера буфера драйвера;
3. блок конвертируется в формат выходов, остальные выходы драйвера
   заполняются нулями;
4. `ASIOOutputReady`, если драйвер его поддерживает (ASIO-008).

Без аллокаций, блокировок и логирования; panic перехватывается по
ADR-005 (тишина до переоткрытия).

**ASIO-033.** Форматы — ASIO-005; дополнительно `Int24LSB` упакованный
(3 байта) и `Int32LSB16/18/20/24` (выравнивание младших бит) [VERIFY по
заголовкам SDK]. Неподдерживаемый формат канала — ошибка открытия с
названием формата. Конвертация в обе стороны покрыта unit-тестами на
граничных значениях.

**ASIO-034.** Размер буфера: engine принимает любой фактический размер
блока (Amendment 01 §8); размер берётся из `ASIOCreateBuffers`, а не из
запроса.

**ASIO-035.** Сообщения драйвера — ASIO-007. Дополнительно:
- `kAsioResetRequest` / `kAsioBufferSizeChange` во время записи:
  запись останавливается с сохранением валидной части (как overflow,
  spec-0.2.0 §7), затем драйвер переоткрывается;
- смена частоты драйвером (`sampleRateDidChange`): транспорт
  останавливается, драйвер переоткрывается, плагины переинициализируются
  (AUD-014); timebase проекта не меняется;
- `kAsioOverload` [VERIFY наличие в SDK] — счётчик перегрузок в
  статистике потока.

**ASIO-036.** Сторожевой таймер: если при запущенном потоке
`bufferSwitch` не приходит дольше `max(1 с, 20 буферов)`, поток
считается упавшим (отключение устройства, AUD-004): транспорт стоп,
уведомление, без переключения на другое устройство.

**ASIO-037.** Статистика (StreamStats): число callbacks, наблюдаемый
размер буфера, поздние callbacks — по разнице `samplePosition` и
системного времени из `ASIOTime`, если драйвер их даёт; иначе поле
«не поддерживается драйвером», не ноль.

### 3.4. Запись через ASIO

**ASIO-040.** При активном ASIO запись (spec-0.2.0 §7) берёт вход из
**того же драйвера**: Options › Recording показывает входы драйвера с
их именами; другое устройство входа при ASIO недоступно (одна
конфигурация, без агрегации) [Д: на Windows для записи используется
ASIO-драйвер].

**ASIO-041.** Смена входа записи требует пересоздания буферов драйвера
(ASIO-031): выполняется при остановленном транспорте, с короткой
паузой звука; во время записи выбор входа заблокирован.

**ASIO-042.** Выравнивание записи: позиция дубля = позиция транспорта на
момент `samplePosition` блока минус (задержка входа + задержка выхода)
из `ASIOGetLatencies`, плюс ручная поправка (spec-0.2.0 §7). Задержки
вычитаются один раз; в статусе записи видно, какие значения применены.
Без измерения петлёй (loopback) не заявлять sample-accurate
выравнивание.

**ASIO-043.** Индикатор уровня входа и монитор работают от тех же
буферов, что и запись (без отдельного потока входа).

### 3.5. Проверки

**ASIO-050.** Тестовый драйвер: в `audio-asio` (под `cfg(test)`) —
внутрипроцессный объект с интерфейсом драйвера на Rust. Он позволяет
без железа проверить:
- полный цикл открыть → играть → закрыть 50 раз без утечек;
- `kAsioResetRequest` и `kAsioBufferSizeChange` из «драйвера» во время
  воспроизведения и записи;
- сторожевой таймер (драйвер перестаёт вызывать `bufferSwitch`);
- все форматы ASIO-033 на входе и выходе;
- запись дубля и его позицию с заданными задержками;
- зависание `ASIOInit` (таймаут 5 с, UI не блокируется).

**ASIO-051.** CI: Windows-job собирает и тестирует workspace с feature
`asio`; Release-workflow собирает MSI с ASIO. CI без звуковой карты не
подтверждает работу с железом.

**ASIO-052.** Ручные проверки без профессиональной карты [Н]:
FlexASIO и ASIO4ALL, установленные пользователем (приложение их не
поставляет и не скачивает) [VERIFY лицензии]: перечисление, панель
драйвера, воспроизведение 10 мин, запись 1 мин, смена буфера из панели
во время работы.

**ASIO-053.** Аппаратная приёмка — ASIO-010 (Audient), плюс запись:
mono и stereo вход, 44.1 и 48 kHz, буферы 128/256/512, дубль 10 мин,
проверка смещения дубля петлёй выход → вход. Без устройства — NOT RUN.
Отчёт по Amendment 02 §0.3.

## 5. Сквозной сценарий

1. Открыть проект 0.2.1 с аудиоклипами на дорожках с разными
   маршрутами; сравнить render с 0.2.1 (ACH-063).
2. В Channel Rack включить фильтр «Audio»: каналы созданы миграцией и
   направлены в прежние треки.
3. Перетащить сэмпл из библиотеки на Playlist дважды: один канал, два
   экземпляра. Перетащить другой файл из файлового менеджера ОС,
   поставить третий сэмпл из Project Browser инструментом Draw, вынести
   выделение из Sample Editor: у каждого сэмпла есть канал в Channel Rack,
   и каждый можно направить в трек микшера.
4. Выделить канал, выделить трек 3 в микшере, Ctrl+L: оба экземпляра
   звучат через трек 3 и его эффекты.
5. Make unique на одном клипе: новый канал, направить его в трек 4.
6. Windows: выбрать ASIO-драйвер, открыть панель драйвера, сменить
   буфер; приложение переоткрывает драйвер, конфигурация обновилась.
7. Выбрать вход драйвера по имени, «В трек» = «Новый трек», записать
   два дубля: два аудиоканала в одном новом треке.
8. Удалить канал первого дубля с его клипом, undo, redo.
9. Сохранить, открыть заново, экспортировать WAV и MP3: каналы,
   маршруты и дубли на месте и звучат.

Для шагов 6–7 указать драйвер, устройство и версию драйвера; синтетический
драйвер (ASIO-050) аппаратную проверку не заменяет.
