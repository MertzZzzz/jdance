# ADR-006: ASIO через собственный адаптер

- Статус: ACCEPTED
- Дата: 2026-10-22
- Требования: ASIO-001…010 (Amendment 02 §6), ASIO-011…053 (spec 0.2.2)

## Контекст

Нужен ASIO-host на Windows: сторонние драйверы, панель драйвера, имена
каналов, реакция на сброс драйвера, запись входа тем же драйвером.
Таблица возможностей CPAL 0.18.2 для ASIO — `docs/audio/cpal-capabilities.md`.

## Варианты

1. **CPAL feature `asio`.** Нет панели драйвера, имён каналов, стабильного
   ID (только имя). Сборка требует libclang и скачивает SDK из сети во
   время сборки — CI и сборка MSI зависят от сайта Steinberg.
2. **asio-sys напрямую.** Те же требования к сборке; панели нет в
   безопасном API, нужно вызывать сгенерированные функции C++-обёртки SDK.
3. **Собственный адаптер `crates/audio-asio`.** Драйвер — COM-объект:
   создаётся по CLSID из `HKLM\SOFTWARE\ASIO`, методы вызываются через
   таблицу виртуальных функций интерфейса драйвера. Описание интерфейса
   и структур переписано по заголовкам ASIO SDK (GPLv3) и сверено с
   привязками asio-sys 0.4.0 (Apache-2.0). C++-часть SDK не нужна.

## Решение

Вариант 3.

- Логика сессии (открытие, формат, буферы, обратные вызовы, сброс,
  сторожевой таймер) не зависит от COM и проверяется на всех ОС с
  тестовым драйвером на Rust (ASIO-050).
- COM и реестр — только `cfg(windows)`; backend «ASIO» появляется только
  в сборке для Windows.
- Все вызовы драйвера, кроме `outputReady`, идут из одного рабочего потока
  с COM STA и циклом сообщений Windows (панели драйверов — окна); ответа
  ждут не дольше 5 с (ASIO-009, ASIO-031).
- Обратные вызовы драйвера не имеют контекста: одна активная сессия на
  процесс (Amendment 01 §6), состояние — в статической ячейке.
- `unsafe` — только в этом crate (`#![allow(unsafe_code)]`), каждый блок с
  комментарием SAFETY; panic в обратных вызовах перехватывается (ADR-005).

## Последствия

- Нет зависимости от libclang и от сети при сборке; SDK в репозиторий не
  кладётся.
- Раскладку интерфейса драйвера поддерживаем сами; ошибка в ней ломает
  все драйверы сразу — поэтому раскладки покрыты тестами размеров и
  проверяются тестовым драйвером, вызываемым через ту же таблицу функций.
- 32-битные драйверы не поддерживаются (приложение 64-битное).
- Аппаратная приёмка (ASIO-053) — отдельно, на реальном интерфейсе.
