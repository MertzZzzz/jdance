# План 0.2.0: аудит базы 0.1.0 и решения

Требования: `docs/spec/spec-0.2.0.md`, `docs/spec/spec-0.2.0-piano-roll-tools.md`
(раздел 18), `docs/spec/ui-visual-spec.md` (UI-VIS).

## Baseline 0.1.0 (2026-10-21)

- Ветка `0.2.0` от `master` 2c71f15 + спецификация UI-VIS.
- `cargo test --workspace`: 218 тестов, все проходят.
- clippy на трёх целях (`-D warnings`) и `cargo xtask check` чистые.
- CI на Linux, Windows и macOS зелёный, MSI v0.1.0 опубликован.

## Аудит: что уже есть

|---|---|---|
| Playlist: lanes, PatternClip | есть; клип = `start` + `repeat`, длина вычисляется | `domain/playlist.rs`, `commands/playlist.rs`, `ui/playlist.rs` |
| Audio clips | нет | — |

| Автоматизация | есть, но *иная модель*: lanes на song timeline (ADR-014) с Hold/Linear/Curve; цели: громкость, pan, send, параметры эффектов, bypass, VST3 | `domain/automation.rs`, engine `bind_automation` |
| VST3 hosting | есть: эффекты и инструменты, сканер в отдельном процессе с blocklist и кэшем, пути в настройках | `plugin-vst3`, `app/plugins.rs` |

| ID нот | у нот нет ID (идентичность по значению) | `domain::Note` |

## Решения

**D1. Автоматизация → AutomationSource + AutomationClip (0.2-F).**
- Текущие lanes мигрируют: lane → source (те же точки, позиции
  относительно начала) + один clip на дорожке автоматизации, от 0 до
  max(последняя точка, конец аранжировки).
- Отличие от 0.1.0: после конца clip значение возвращается к ручному.
  В пределах аранжировки звук не меняется — это проверит golden-тест
  автоматизации.
- Формы Hold/Linear/Curve сохраняются: Hold = step, Curve — наше
  расширение.
- Цели 0.1.0 остаются; добавляется gain AudioClip.
- Реализация (формат v12): `AutomationLane` стал источником (`name`,
  `length`), `Playlist.automation_clips` хранит клипы (`start`,
  `offset`, `duration`, `muted`, без loop). Миграция — на lane по
  клипу длиной «конец аранжировки + такт»; длина песни не меняется
  (клипы автоматизации её не удлиняют).
- Несколько источников на одну цель допустимы; пересечение клипов
  одной цели отклоняется при правке с сообщением.
- Источники удалённых объектов (дорожка, канал, клип) не удаляются, а
  показываются как «target not found»; undo восстанавливает связь.
- Движок: на цель — один `AutomationRt` с окнами клипов; вне окон
  цель возвращается к ручному значению через обычное сглаживание.

**D2. Project timebase.**
- `Project.timebase_rate` (по умолчанию 48 000) сохраняется в проекте.
- AudioClip хранит позиции в кадрах этой частоты.
- Движок переводит их в кадры устройства при компиляции snapshot.
- Ассеты ресемплируются до частоты движка уже существующим фоновым кэшем.

**D3. Воспроизведение AudioClip без состояния.**
- Значение в момент `t` — чистая функция позиции:
  `source = src_in + (t − start)`, плюс fades.
- Поэтому seek внутрь клипа, циклы и смещения PDC (чтение со сдвигом
  на задержку трека) работают без особых случаев.
- Клипы смешиваются во вход шины дорожки (Lane.audio_track,
  по умолчанию Master).

**D4. Ассеты в проекте.**
- Импорт копирует файл в `<проект>/assets/`.
- Дубликаты определяются по размеру и хэшу FNV-1a 64 содержимого (не
  криптографический, только для идентичности).
- Пока проект не сохранён, ассет хранит абсолютный путь; при сохранении
  он копируется в `assets/`, путь становится относительным.
- Внешние оригиналы никогда не изменяются и не удаляются.

**D5. PatternClip: `offset`, `duration`, `looped`** вместо `repeat`.
Миграция: `offset = 0`, `duration = repeat × length`, `looped = true`.

**D6. Ноты получают `NoteId`** (u64 из общего аллокатора) — этого
требует раздел 18 (стабильные ID, split). При миграции ID назначаются
по порядку.

**D7. Dock/Undock — native viewports egui** (`show_viewport_immediate`).
- Отдельное окно ОС той же сессии.
- Layout хранится в настройках.
- Окна вне видимой области возвращаются на основной монитор.

**D8. Запись — вход того же устройства и той же частоты** (cpal,
два потока одного device).
- Если вход у устройства недоступен или частоты не совпадают — ошибка;
  скрытой агрегации нет.
- Кадры идут в bounded SPSC → writer-поток → WAV float32.

**D9. MP3 — LAME через crate `mp3lame-encoder`** (LGPL, сборка LAME из
исходников через `cc`, без системной зависимости). Перед подключением
проверить лицензию и сборку на трёх ОС в CI.

**D10. Скрипты — Rhai** (MIT/Apache-2.0, чистый Rust).
- Лимиты операций, глубины вызовов и размеров коллекций.
- Прерывание через `on_progress`, выполнение на worker-потоке.
- Только чистые функции над снимком нот; файлов, сети и процессов нет.

**D11. Плагины (§6).** Hosting уже есть, поэтому интеграция идёт с
существующим реестром:
- пути с включением и выключением;
- прогресс и отмена scan;
- список ошибок и карантин;
- выбор только `.vst3`.

## Этапы

Порядок из спецификации. UI-VIS-доработки встроены в этапы, которых они
касаются.

1. **0.2-A** — AudioAsset, AudioClip, timebase, waveform в клипе, drop
   из Browser и ОС в Playlist, routing lane → шина, движок, миграция v11.
2. **0.2-B** — PatternClip offset/duration/loop (миграция), resize
   обоих краёв для всех клипов и нот, Slice.
3. **0.2-C** — Project Browser слева от Playlist (Patterns, Samples,
   Automations), Sample Selection Dialog, настройки библиотеки
   (recursive, rescan, отображаемое имя, unavailable), защита от
   циклов symlink.
4. **0.2-D** — инструменты Draw, Paint, Delete, Slice с иконками
   (UI-VIS-041) и единой keymap в Playlist и Piano Roll; единая шапка
   окон (UI-VIS-030).
5. **Sample Editor** (§3): двойной клик по объектам.
6. **0.2-F** — AutomationSource и AutomationClip, редактор, gain/pan,
   gain клипа. Готово.
7. **0.2-E** — запись. Готово: вход через `AudioBackend::open_input`
   на частоте вывода (другое устройство — с предупреждением о дрейфе
   часов, без агрегации), кольцевой буфер 20 с → поток записи WAV
   float32 `*.wav.part` → переименование; переполнение и ошибка диска
   останавливают запись с сохранением записанного; мониторинг (по
   умолчанию выкл., с предупреждением) через кольцо в выходной
   callback; ручной offset; восстановление незавершённых файлов при
   старте. Проверено с ALSA null-устройством (нули без тактирования);
   запись с реального железа — NOT RUN.
8. **0.2-G** — Dock/Undock. Готово: Piano Roll, Sample Editor,
   Automation Editor, Mixer, Project Browser выносятся в нативные окна
   (egui viewports, `show_viewport_immediate`) той же сессии: View →
   Own windows, кнопки Undock/Dock back, Reset layout; закрытие окна
   скрывает панель; расположение и размер хранятся в user settings,
   позиция за пределами экрана возвращается в видимую область.
   Shortcuts редакторов работают в окне, где у них фокус; transport
   (Space и т.п.) — в главном окне. Проверено под Xvfb (X11, без
   оконного менеджера); Windows/macOS, multi-monitor и HiDPI — NOT RUN.
9. **0.2-H** — пути плагинов и scan UI. Готово: стандартные и
   пользовательские пути VST3 с enable/disable (в user settings),
   add/remove, rescan/full rescan, прогресс по модулям, отмена
   (недосканированные модули сохраняют прежний результат), список
   найденных плагинов и ошибок. Сканер уже был отдельным процессом с
   таймаутом и blocklist (PLG-022/024).
10. **0.2-I** — MP3. Готово: формат WAV/MP3 в диалоге экспорта,
   рендер на частоте MP3, кодирование блоками, `*.part` → rename,
   прогресс и отмена (WAV тоже), предупреждение о перегрузке выше
   0 dBFS, CLI `--format mp3 --bitrate N`.
11. **0.2-J…N** — Piano Roll Tools и скрипты. Готово: стабильный
   `Note.id`; чистый модуль `commands::note_tools` (scope, границы,
   SplitMix64 v1, лимит 100 000 нот) со всеми инструментами §18.3–§18.21;
   диалоги с живым Preview от исходного снимка, Apply (один шаг undo),
   Cancel/Reset, подтверждение выпадающих нот; быстрые команды сразу;
   LFO пишет точки в AutomationSource (новый — без клипа) и открывает
   Automation Editor. Скрипты: crate `jdance-scripts` на Rhai 1.27
   (без модулей, eval, I/O; лимиты операций, глубины, размеров, времени;
   отмена), выполнение на рабочем потоке, пять встроенных скриптов и
   пользовательская папка `<config>/scripts`. Последние настройки
   инструментов хранятся в памяти сеанса (не в user settings).
12. **Mixer по UI-VIS §8** (вертикальные полосы, инспектор).
13. Версия 0.2.0, статус, сборка MSI.

## Риски

- Объём: каждый этап — вертикальный срез с тестами, коммит после
  каждого.
- Dock/Undock на Windows/macOS не проверить под Xvfb. Нужна проверка
  на реальных ОС; до неё в статусе — NOT RUN.
- Запись с реального железа в среде разработки невозможна: только
  синтетические тесты. Hardware-проверка — NOT RUN (§15 спецификации).
- LAME и `cc` на Windows MSVC и macOS проверяются только в CI.
